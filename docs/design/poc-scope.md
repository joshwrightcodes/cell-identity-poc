# Cell identity PoC: build scope

Status: draft for owner review. Date: 2026-11-08.

This document says what the first build proves, and nothing more. The full design is in
`docs/design/target-architecture.md`. Where this document names a mechanism, the target
architecture describes it, and this document gives the simpler PoC form. Source markers follow
the target architecture: **[owner]**, **[call]** and **[canon]**.

## What the PoC proves **[owner]**

On one Mac, with no credential copied between clusters:

1. The portal requests two new cells, and the environment control plane creates them.
2. Each cell's `celld` registers and authenticates with its environment control plane.
3. Both cells appear in the management plane as valid, from proof that only the cells can produce.
4. A third, malicious cell is rejected, and so is a man in the middle.

It also shows three properties that the owner set:

- Island mode: an environment cut off from the management plane, and a cell cut off from its environment control plane, keep working on their last known state.
- A read-only central Argo CD view in the management plane, which cannot change a cell.
- Central observability in the `management` cluster: logs, metrics and traces from every cluster in one Grafana, and one Kiali view of each cell's mesh. Signals cross clusters only as OTLP, over SPIFFE mTLS.

## What is in scope

| Area | PoC form | Target architecture section |
| --- | --- | --- |
| Clusters | `management`, `dev-cp`, `dev-cell-1`, `dev-cell-2` and `rogue`, as kind clusters in one Colima VM | Topology |
| Provisioning | The cell controller in `dev-cp` sends a step that the management plane signs to a host service on the Mac. The host service creates the cluster and applies the pinned bootstrap set | Cell controller |
| Cluster keys | The host service serves each cluster's JWKS over TLS with a certificate that the management plane pins. The management plane binds the issuer with a nonce token at first start | Independent key check |

| Attestation | `cluster_jwt` with pod-bound tokens of 15 minutes or less. Agents do not re-attest: each attestation gets a fresh agent ID, and running agents renew without a new token | Attestation |
| Specs | The management plane stand-in signs specs and cell records with one key. envd pulls them, and refuses unsigned or older ones | Signed specs and records |
| Work | `celld` holds one stream to the cell gateway, claims operations that the management plane signs, and applies each one at most once by operation ID | Signed work and idempotency |
| Proof to the management plane | `celld` sends status and results with a projected token whose audience names the management plane and binds the item: the body digest of a report, the TLS session of a stream, or the nonce of a bind. | The management plane's root in cells | Pinned in the bootstrap set, and read from a static file, never from the Workload API | Network flows |
| Bundles | `celld` in each cell and envd in `dev-cp` apply bundle sets that the management plane signs. Each applier pushes the bundles to the bundle store, and Argo CD applies them. A rollback points the root back at the last good root that the management plane signed | Bundles, Argo CD and safe updates |
| Central view | Argo CD Agent in autonomous mode, with the principal in `management`. Agents connect through `cell-proxy` and a TLS passthrough relay in `dev-cp`. An admission policy in the cell blocks every write, every annotation except refresh, `.operation`, and exec | Central Argo CD view |
| Observability | The `otel-lgtm` image in `management` runs Grafana, Loki, Tempo and Prometheus. Each cluster's collector scrapes local Prometheus endpoints and receives OTLP. It exports OTLP through `cell-proxy` and the telemetry relay to a gateway in `management` | Telemetry |
| Mesh view | Kiali in `management` reads mesh metrics from the stack. It reads each cell's mesh state through a tunnel that the cell's `cell-proxy` opens up to `management` | Mesh view |
| Island mode | Both levels, with no trust change during an island | Island mode |
| Revocation | The management plane revokes in a spec. During an island, an operator revokes locally, and the overlay holds until a spec from the management plane includes it | Revocation |

## What is not in scope

These stay in the target architecture, and come in later increments:

| Deferred | Why it can wait |
| --- | --- |
| Approver signatures checked in cells | Needs approver tooling. The PoC's claims do not depend on it |
| Customer-data operations, encrypted exports, exploration sessions | A separate capability on top of signed work |
| Key sets, the recovery key and its ceremonies, root rotation | The PoC uses a fixed root. `pki:rotate-intermediate` replaces the intermediate CA, and `mgmt -- rotate-signing-key` replaces the signing key of `mgmtd` |
| Restore with epochs, rebuild from empty, provider inventory and the sweeper | Disaster recovery work, once the core holds |
| Relay hardening: outer mTLS, per-cell caps, revocation at the relay | The PoC relay only passes TLS through. The management plane enforces identity |
| Watchdog and blue/green updates of `celld` and Argo CD | In the PoC, the harness updates `celld`, and a bundle updates Argo CD. The residual limits say what a bundle can still change |
| HPA fan-out, cross-environment requests, alert evaluators, the personal-data canary test | Scale and operations work |
| EKS, ACK, the tailnet and AWS-specific network rules | The second environment target |
| Integration tests in GitHub CI | Hosted runners for private repositories have 2 CPUs and 8 GB. CI runs unit and component tests only |

## Simplifications **[call]**

- One signing key for the management plane, one environment, one SPIRE server, and no HA.
- The queue in `dev-cp` and the SPIRE datastore use SQLite on persistent volumes.
- Every cluster uses the local-path provisioner that kind ships, after the vendor review. The bundle store moves to a persistent volume.
- `celld`, envd and their Deployments are outside every Argo CD Application, and the harness applies them. The target also keeps Argo CD outside every Application, and the PoC does not. Instead, the guard `bundles-spare-harness` and the policy of each applier keep bundles away from every harness object. The residual list says what is not in place yet.
- The relay is a TLS passthrough that routes by port. The management plane has one listener for `dev`.
- Each cluster gets its own pod and service subnets. Pod networks are not routed between clusters, so cross-cluster traffic uses node addresses on the `kind` network.
- `harness:up` creates `management`, `dev-cp` and `rogue` directly, and the two cells through the portal.
- Observability uses the `otel-lgtm` all-in-one image, with local storage and no HA.
- The management plane stand-in keeps its key and its state in files on its own persistent volume.
- Upstream components keep their Prometheus endpoints. Only the collector in the same cluster scrapes them, and signals leave a cluster only as OTLP.
- The External Secrets Operator is the provider-neutral sync from the secret manager into each cluster. A cluster gets its own install when it first needs a secret. In M2, only `dev-cp` has one. In M3, `management` has an operator with no store, for its Password generator.

## Milestones

Each milestone ends with an automated test, and each test runs only once the thing that stops
it exists.

| # | Milestone | Done when |
| --- | --- | --- |
| M0 | Base cell | Done |
| M1 | Harness | The host service creates all five clusters twice from clean, with storage and one registry mirror. A pod in `rogue` reaches no port on a cell's node except the residual ports 2379, 2380, 6443, 10250 and 10256 |
| M2 | Attestor | Against a test-signed record, `celld` gets an SVID. Pod-bound, lifetime, audience, subject and unknown key ID tests fail as expected. A sidecar renews without a new token |
| M3 | Central view and observability | `management` shows both cells in one Argo CD UI, with live manifests. Writes, annotation changes, `.operation`, exec and Secret reads through the view fail. A cell's SVID cannot pose as the management plane's principal. Grafana shows logs, metrics and traces from every registered cluster, each tagged with its cluster, plane, environment and cell. A cell that labels its signals as another cell's is corrected at the gateway, and telemetry from `rogue` fails. Kiali shows the mesh of each cell, and cannot change it |
| M4 | Management plane stand-in and specs | envd pulls signed specs, and refuses unsigned or older ones. The management plane binds issuers and checks keys. The test-signed record fixture is deleted |
| M5 | Signed work | `celld` claims, verifies and applies operations once. Forged, replayed, expired and wrong-target items fail. `dev-cp` cannot pose as a cell to the management plane on the view, telemetry and mesh view streams |
| M6 | Provisioning end to end | Checks 1–3 pass from one portal request. A step with no management plane signature fails |
| M7 | Malicious cell and MITM | Check 4 passes. A rogue cluster, a rogue JWKS, TLS interception at each hop, and a relay that alters bytes all fail |
| M8 | Bundles | Bundles that the management plane signs reach Argo CD in each cell and in `dev-cp`. A bundle outside its allow-list fails, and a rollback restores the last good root |
| M9 | Island mode and revocation | Both island levels hold for three SVID lifetimes, with no pod restarts. Revocation works connected and locally |

The full gate runs on the Mac, with a fast tier for M1–M8 and a slow tier for M9. Each tier has a
time budget, set at M1. The Mac must stay awake for the whole gate, so a keep-awake tool must run.
macOS still sleeps when the lid closes on battery power.

## Residual limits of the PoC

- Locally, every cluster shares the `kind` network, so clusters can reach each other's Kubernetes API, kubelet, etcd and kube-proxy health ports. The residual ports are 2379, 2380, 6443, 10250 and 10256. On 2026-11-08 a scan of ports 1 to 65535 from `rogue` found exactly these ports open on each node of `management`, `dev-cp`, `dev-cell-1` and `dev-cell-2`. The M1 test fails if any other port opens. It also fails if port 6443 or 10250 is closed, because then the scan did not work. The scan covers TCP over IPv4 only. The `kind` network is dual-stack with the IPv6 prefix `fc00:f853:ccd:e793::/64`, and no test scans the IPv6 node addresses. A NodePort Service with no ready endpoint does not show as open.
- Every cluster shares the registry `registry-mirror`, which accepts a push without authentication. The container starts with the delete switch off, so a delete by digest from a pod is refused. The namespaces that the bundles own deny that egress. Pods in a namespace without NetworkPolicy still reach the registry: `kube-system`, `default` and `local-path-storage` in each cluster, and every namespace of `rogue`. Host network pods and new pods in the kindnet window below reach it too. Each render pins a local image by the digest that `mise run images` recorded on this Mac, and it computes a plugin checksum from the image at that digest. So a pushed tag cannot change a render. Those pods can still push new tags. The host service replaces a mirror that lacks the delete switch, and it keeps the volume.
- The same pods reach every listener on the loopback interface of the Mac through `host.docker.internal`, not only the host service. The owned namespaces deny that egress.
- A compromised management plane can sign any work. Approver checks in cells come later.
- A run keeps its roots. Three tasks replace a key: `mise run pki:rotate-intermediate` replaces the intermediate, and `cell:verify` in `dev-cp` fails 7 days before it expires. `mise run mgmt:rotate-ca` replaces the management root, and `mise run view:rotate-keys` replaces the view keys. `mise run mgmt -- rotate-signing-key` replaces the signing key of `mgmtd` as a break-glass action. No task rotates the root of `dev-cp`. The M2 key rotation test changes the signing key of `dev-cell-1` for two to three minutes, and then restores it.
- The fast tier runs with SVIDs of 1 minute, and the slow tier with SVIDs of 1 hour. `SPIRE_SVID_TTL` in `cells/dev-cp.env` and `GATE_M9_SVID_TTL` in `harness/versions.env` set them. Both apply to agents and workloads. After a pause longer than the remaining lifetime, for example while the Mac sleeps, an agent cannot renew. The rotator then ends the agent (`pkg/agent/svid/rotator.go:102-105` in v1.15.5), and the restarted container attests as a new agent. The server keeps the old agent entries until it prunes them. `TestM9IslandsHold` verifies the exit at expiry in its subtest `svids_lapse`, and the restart in its subtest `reattest`.
- Any identity that can create a pod in `cell-identity-system` can run it as the `celld` service account, and so attest as that cell. It also gives the right to write to the bundle store and to patch `root`. The rejection tests rely on this. In each cell, the Argo CD application controller could create a token for any service account there. The guard `bundles-spare-harness` now denies that request in the harness namespaces. `istiod` cannot create a token there, but it can create Deployments and ServiceAccounts in every namespace (ClusterRole `istiod-gateway-controller-istio-system`). Because of this, `istiod` can also run a pod as `celld`. On 2026-11-09, `kubectl auth can-i` confirmed each of these rights in `dev-cell-1`. Admission control that limits pod creation and token requests there comes later.
- In `spire-system` of `dev-cp`, several service accounts can read Secret `spire-upstream` with the intermediate CA key, and the copy of the access token. They are the Argo CD application controller, `istiod`, `istio-system/istio-reader-service-account` and the External Secrets Operator. The garbage collector and the namespace controller in `kube-system`, and cluster administrators, can read them too. `istio-reader-service-account` can read Secrets in every namespace.
- The intermediate CA key and the access token rest unencrypted in the etcd of `dev-cp`, on the disk of the VM. The kind clusters do not encrypt Secrets at rest. No script writes a key to a file, but etcd stores each Secret.
- The bundles of `dev-cp` come only from sets that the management plane signs, and envd applies them. In `dev-cp`, the harness components stay unsigned. The bootstrap root has no signature until the first signed set. A break-glass publish and a repair carry no signature of their own. The writers of ConfigMaps in `spire-system` keep the reach that the other residual lines name. `management` keeps the harness publish, so its bundles stay unsigned.
- The SPIRE server NetworkPolicy admits by the node address of each agent cell, so admission is per node, not per workload. Each pod that the policies of its own namespace let out reaches the SPIRE port, and the token checks of the plugin decide which pod attests.
- kindnet accepts each packet of a root process in the host network (`meta skuid 0`) before it checks a NetworkPolicy. Because of this, NetworkPolicy does not constrain root processes on a node, or root host network pods. On the `dev-cp` node, every root process reaches the SPIRE server port 8081 with no check. Examples are host network pods in `kube-system`, and the `pods/proxy` and `services/proxy` paths of the API server.
- One shared vault and one access token serve `dev-cp`. `management` holds no token. Because of this, a compromised `dev-cp` can read every PoC secret, including the SPIRE intermediate key. Production gives each cluster its own token and vault.
- The External Secrets Operator in `dev-cp` reads and writes only the Secrets of `spire-system`. Its NetworkPolicy still admits DNS and every public address on TCP port 443, so the operator can reach any public host on that port.
- The External Secrets Operator in `management` reads and writes every Secret in `observability-system`, Secret `grafana-admin` included. Its NetworkPolicy admits only DNS and the API server.
- The relay does not close the streams of a revoked cell. The `cell-proxy` servers and the cell gateway close them.
- The relay limits open connections to 256 in all and 16 for each client address. A cell node address stands for every pod of that cell, so one pod can use the 16 slots of its cell. One limiter serves every route of a relay, so silent connections on one route use slots of the other routes too. The management view listener keeps 64 handshake slots for all cells, and a client that sends one byte takes one for 10 seconds. Two cells with 16 connections each cannot fill them, but the relay has no limit for each cell beyond the address.
- Every pod of a cell that no NetworkPolicy limits reaches the relay node ports through the node address of its cell. In `dev-cp`, such a pod reaches `management` on 31443 directly. An address spoofed on the `kind` bridge reaches the same ports. Identity at cell-proxy is the control, as for the SPIRE node port.
- The identities `argocd/argocd-agent`, `observability-system/otel-uplink` and `mesh-view-system/mesh-view` follow the same rule as `celld`: any identity that can create a pod in the namespace can run it as that service account. The agent pod can request a token for its own service account, so it can attest as a node. The agent exposes `/debug/pprof` on its health port, and the pod admits no ingress to it. ConfigMap `mgmt-root` can be overwritten by a bundle that writes to `argocd`, and the new root applies at the next pod start.
- The agent can list and watch every Secret of `argocd`, because it does not start without that access. The admission policy limits the Secret names and not their contents.
- A revoked record stops new attestations. The kubelet syncs ConfigMap `cell-records` into the pod, which takes up to about a minute. After the pod holds the record, the plugin reloads it within 10 seconds, and a container beside the SPIRE server bans the agents of the cell within 10 seconds.
- A ban takes effect in about 4 seconds. The restart of a banned agent attests as a new agent within 1 second, so a ban alone does not stop a cell. The overlay and the refusals of the record stop it.
- A holder of the operator key can revoke any cell, and `mgmtd` adopts each revocation at once.
- While the secret manager is unreachable, an operator cannot revoke a cell locally.
- The Mac administrator can change every operator key pin. `operator:check-key` compares the pin ConfigMaps and `server.conf` with the key in the secret manager. It does not read the keys that the running processes loaded. A writer in `dev-cp` can change a pin, restart the process, and restore the pin, and the check then reports a match.
- A writer of `cell-records` can replay an old signed entry across a restart of `envd`, because `envd` keeps no spec marks elsewhere. The cell stays revoked until an operator runs a revoke and then an un-revoke. The un-revoke rule of `mgmtd` refuses to adopt the entry again.
- A corrupt gateway store holds no overlay until the next sync of `envd`. This takes about 10 seconds while `envd` runs, and longer while `envd` is down.
- `mgmtd` keeps an unbounded mirror of revocation events. Only an admin action or a signed entry adds an event.
- The overlay of the gateway and `envd` counts a hold of more than 10 minutes from `issuedAt`, because `envd` records no admit time.
- `revoke -- clean` deletes only stale and settled input keys. A key that does not verify needs a manual delete, and `harness:status` prints the command.
- `mgmtd` reads the cell keys from the host service on the Mac. It checks each bound cell every 15 minutes, whether or not `dev-cp` is connected.
- `operator:rotate-key` refuses during a cut, or while `dev-cp` is not connected, before it reads the secret manager. The message names the cut or "not connected". The option `--emergency` needs no old key.
- The SPIRE server pod of `dev-cp` sends OTLP to the collector on TCP 4317, and resolves DNS. The DNS rule admits only the cluster DNS pods and the DNS Service address. CoreDNS can still forward names outside the cluster, so the server pod can send data out in DNS queries (not verified live). This is the one network flow that M9 adds. The collector admits every pod of `spire-system`, so any pod there can send signals as that namespace.
- The island signals have no alert evaluator.
- The collector queue of `dev-cp` grows by `<measured in the live part>` in an environment island. This projects to `<measured in the live part>` in 24 hours, against a cap of 1.5 GiB.
- An operation expires 1 hour after its signature, so work queued before a longer island never applies. A bundle set is an operation too.
- The `celld` status carries no Argo CD health and no collector drops.
- In the cell island of 2026-11-22, the agents of the cell exited 5 to 39 seconds after their SVIDs expired. Each container restarted in place and attested as a new agent after the heal. The cell kept every pod. Every agent was Ready within 18 seconds of the heal.
- Workload API clients take a new SVID within about 11 seconds after their agent returns, by design. The retry caps give this bound, and the live value is `<measured in the live part>`. The stream retry of `celld` stops at 5 seconds.
- An environment island restarts no container. In the run of 2026-11-22, the outbox grew to 18 items in 4 minutes and drained in 19 seconds.
- The Colima VM clocks stop while the Mac sleeps, and `istio-agent` renews on the monotonic clock. After a long sleep, a sidecar keeps an expired certificate.
- The `istio-proxy` liveness probe restarts only that container when its certificate has 2 hours or less left. The egress gateway has no such probe, and `cell:verify` reports its certificate.
- The SPIRE node port has no limiter before authentication, which the target architecture requires for each plane listener. SPIRE also limits no attestation per address (`ratelimit { attestation = false }` in `server.conf`). The plugin limits each cell only after a token validates, and it limits no failed attestation. A payload with an unknown cell name ends before the in-flight cap. Because of this, failed attestations have no rate limit.
- Each cell has at most 8 attestation streams in flight (`per_cell_inflight`). Each stream waits up to `challenge_timeout`, 10 seconds, for the reply to its challenge. A client that opens a new stream each time an old one ends keeps all 8 slots full. This blocks every new attestation of that cell for as long as the client continues. The client needs no credential. The SPIRE port admits the node address of each agent cell, and not only the cell that an attestation names. So any pod in a namespace without policies in any agent cell can hold these slots for any cell. Examples are `kube-system`, `default` and `local-path-storage`, and any host network pod. Running agents renew over their existing identity, so only new pods of the cell wait. After a cell island longer than an SVID lifetime, every agent of that cell attests again, so the flood also delays its recovery.
- A privileged host network pod in `rogue` can claim the address of a cell node with gratuitous ARP on the shared `kind` bridge. It can then reach the SPIRE node port from an admitted address. This gives reach and denial of service only, because an attestation still needs a pod-bound token of the cell. M7 does not test it, by decision of the owner.
- kindnet sends pod packets to its NetworkPolicy process through an nfqueue rule with the `bypass` flag. Without a process on the queue, the kernel accepts the packets. So NetworkPolicy fails open by construction while the kindnet pod of a node restarts. The cleanup of the M2 key rotation test and `gate:m2:repair` restart the kindnet pod of `dev-cell-1` when its projected token comes from the test key.
- kindnet applies NetworkPolicy to a pod only after it adds the pod address to its nftables sets. Until then no queue rule matches the pod, so both egress and ingress of the pod are open. On 2026-11-09 the egress window took about 2 seconds after the pod became Ready. In that window, the pod reached the internet and the `dev-cp` node port with no policy. Short-lived probe pods in `argocd`, `cell-system`, `observability-system` and `cell-identity-system` all reached the internet in this window. The window repeats for every new pod, so anyone who can create pods can use it again. The PoC accepts this property of the kind CNI, and a production CNI differs. Each `cell:verify` probe records the time to its first blocked dial in `build/<cluster>/verify-probes.log`, and it fails above 10 seconds. `TestM7PolicyWindow` measures the window for a new pod in `dev-cell-1` in a namespace with a policy that denies all egress: the last dial that connected came 807 ms after the start, on 2026-11-18 (four runs, 800 to 807 ms). The test fails when a dial connects after 10 seconds, or when an attestation probe of another subject gets an SVID.
- No CRD carries an Argo CD tracking ID, so Argo CD never prunes a CRD that leaves a bundle. On 2026-11-09 the CRDs of the External Secrets Operator in `dev-cp` had no tracking annotation. A CRD that a bundle drops stays in the cluster, with its objects, until a person deletes it. `eso:migrate` deletes the ClusterSecretStore CRD for this reason.
- The harness apply prunes only the kinds in `HARNESS_PRUNE_KINDS`. A Namespace, a Job, a Secret, a PersistentVolumeClaim and an object with the label `poc.internal/made-by` stay in the cluster until a person deletes them. `cell:verify` reports an extra object of a kind that the bundle holds.
- The guard `bundles-spare-harness` refuses each write of the Argo CD application controller in the harness namespaces and on each harness object. Kubernetes applies no admission policy to ValidatingAdmissionPolicy, MutatingAdmissionPolicy or their bindings (as of 2026-11-18, v1.37). Because of this, the applier refusal `harness_object` and the AppProject blacklist protect the guard itself. A platform bundle can still change Argo CD, the AppProjects and the store.
- A signed `argocd` set can move the identity that the guards match. It can enable sync impersonation in `argocd-cm`, and it can switch the method that tracks objects to labels, which stops the match of `bundles-app-limits`.
- The class `platform` still allows ClusterRoleBinding, webhook configurations and admission policies under names that no rule lists. A hostile platform set is a cluster administrator in effect. The rules of the engine stop mistakes in declared objects, and nothing more.
- A bad `argocd` or `cell-system` set can leave a cluster broken until `mise run bundle -- repair` runs. The repair restores signed content, but no signature covers the act.
- The bytes of each bundle travel through `registry-mirror`. A pod that reaches it can push new tags, fill its disk and overwrite the referrers tag of a cosign bundle. It cannot change a signed digest.
- A holder of `pods/portforward` or `pods/exec` for `bundle-store-0` in `cell-system` writes to the store with no token, through the loopback port 5001. Cluster administrators and the Argo CD application controller hold that right.
- One version covers each set, and no security floor exists. A writer of ConfigMaps in `cell-ops-system` or `envd-system` can lower the mark, and so skip the older-root check of `bundle -- repair`. Op expiry and the operation records still bound a replay.
- The `good` entries of the state ConfigMap `bundle-state` carry no signature. The RBAC of that ConfigMap is the control. A state writer can change the root that a rollback restores. A state writer can also add an entry to `checked`, so that a later signed set skips the policy for that component. The digest stays signed, but nobody checks the content.
- The store proxy keeps an accepted token for up to 30 seconds and a refused token for 10 seconds. It runs at most 8 token reviews at once, and answers 503 `overloaded` beyond that. A token of a deleted service account can still read for up to 30 seconds.
- The store keeps every bundle, with no garbage collection. An applier refills a lost store from its state and the mirror. Its probe does not detect a loss that keeps the blobs of the root manifest.
- Only a harness policy admits each plane flow. The plane policies of `cell-system`, `spire-system` and `relay-system` select every pod of their namespace (`podSelector: {}`). This includes `relay-system/plane-cells`, which admits each live cell address on the route ports. Any pod that a bundle adds there gets the same ingress. The relay plane policies also take the union of the route ports. Each live cell node can reach either relay pod on 8443 to 8445. A compromised relay pod can reach the other upstream on 31443 to 31445. Each relay listens only on its own ports, so the cross pairs reach a closed port.
- The policy cannot see every way to stop plane pods, for example a webhook that changes their pods.
- A signed set that drops Namespace `spire-system`, `relay-system` or `cell-system` makes Argo CD delete that namespace, because the sync prunes. The namespace controller then deletes the plane policies in it. The same set removes the bundle component, so the plane policies are not the first loss. The recovery is a new render of envd.
- `go.sum` lists `prometheus/client_golang` and other modules that OPA or containerd require, and no binary compiles them. `celld` and envd grow by about 15 MB.
- An AppProject cannot limit a Service type or the sidecar opt-out. The applier and `bundles-app-limits` check them.
- `mgmtd` signs every component list of the right shape and reads no bundle content.
- A rollback deletes each Application that only the failed set added, and leaves its resources in the cluster.
- The account of `celld` in a cell, or of envd in `dev-cp`, is the only writer of the store. It also has `patch` on `root` and on each component Application of its role, by name. - Row 1 of the rejection table runs the attestation client of `celld` with a token from `rogue`. `rogue` holds no components, so no full `celld` runs there. The key check is the same code. `TestM2RejectRogueKey` and `TestM5BindRefusalsLive` prove rows 1 and 2, and `TestM4HostServiceServesPinnedKeys` proves the client half of row 9. `gate:m7` does not run them, so run the gates of M2, M4 and M5 at the head of M7.
- No test scans the node of a cell from a host network pod. A host network pod that runs as root passes kindnet policy, so it can reach more ports than a plain pod. `TestM7HostNetworkScan` covers `dev-cp` and `management` only.
- `cell-controller-system` holds the steps and their status in ConfigMaps. A writer there can delay a step or show a false status. It cannot make a cell valid.
- `valid` takes the applied record revision from envd in `dev-cp`, and `lastStatusAt` from the clock of the cell.
- Each admit stage restarts the `dev-cp` SPIRE server and gateway, so other cells can show `status_stale` for a few minutes.
- `cell:down`, a harness command with no signature, deletes cells. A withdrawn cell keeps its admit rule until its `cell:down`, because the admit lists follow the clusters that exist.
- A host service restart or a Mac logout during a step ends the running stage. The step shows `failed` with `interrupted`. It runs again only after the first spec push from `mgmtd` and the next poll of the cell controller.
- A command that finds a stale cluster lock takes the lock over in a window of a few instructions. Two such commands can race for the same dead holder.
- After `--emergency --force` across a stage boundary, a window of about 40 seconds can end the step `failed_final`. The host service trusts the new key before `mgmtd` pushes the new spec.
- The host service reads the node address after the `creating` stage with no timeout. If Docker hangs after a good create, the read holds the actor.
